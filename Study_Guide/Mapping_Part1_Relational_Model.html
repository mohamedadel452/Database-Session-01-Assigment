1) إيه هو الـ Relational Database؟ (سلايد 4 و 5)

الفكرة: البيانات بتتخزن في جداول (relations) من صفوف (tuples) وأعمدة (attributes)، والجداول بترتبط ببعض بقيم مشتركة (Foreign Keys). اقترحه E. F. Codd سنة 1970 على أساس رياضي (نظرية المجموعات والمنطق)، وده سبب إن SQL "set-based" (بتعمل على مجموعات صفوف مرة واحدة مش صف صف).

CREATE TABLE Departments (DepartmentID INT PRIMARY KEY, DepartmentName NVARCHAR(100) NOT NULL);
CREATE TABLE Students    (StudentID INT PRIMARY KEY, StudentName NVARCHAR(100) NOT NULL,
                          DepartmentID INT NOT NULL REFERENCES Departments(DepartmentID));

SELECT s.StudentName, d.DepartmentName
FROM Students s JOIN Departments d ON d.DepartmentID = s.DepartmentID;   -- الربط بالقيمة مش بمؤشرات

ليه "الربط بالقيمة" مهم؟ في قواعد قديمة (hierarchical/network) كانت العلاقات مؤشرات فيزيائية، وأي تغيير في التخزين كان بيكسر البرامج. الموديل العلائقي فصل المنطق عن التخزين: أنت بتوصف "عايز إيه" والـ DBMS بيقرر "إزاي" (query optimizer). ده سبب بقاء SQL 50 سنة.

خلط شائع: كلمة Cardinality ليها معنيين مختلفين: (1) في الـ ER هي نوع العلاقة (1:N و M:N). (2) في الموديل العلائقي (وفي SQL Server execution plans) هي عدد الصفوف في جدول أو نتيجة. وكمان "Cardinality of a column" في الـ indexes معناها عدد القيم المميزة (selectivity). في الامتحان اقرأ السياق.

جدول ≠ Relation بالظبط: الـ relation النظرية مجموعة (مفيش صفوف مكررة ولا ترتيب). جدول SQL ممكن يحتوي صفوف مكررة (لو مفيش PK) وبيرجع بترتيب غير مضمون من غير ORDER BY. عشان كده PK مش رفاهية: هو اللي بيخلي الجدول فعلاً relation.

3) قيود السلامة الثلاثة (Integrity)

النوعالقاعدةبتتطبق بـلو اتكسرت
Entity Integrityالـ PK مش NULL ومش مكررPRIMARY KEYصفوف مفيش طريقة تميّزها
Referential Integrityقيمة FK لازم تكون موجودة في الجدول الأب (أو NULL)FOREIGN KEYصفوف يتيمة (orphans) وتقارير غلط
Domain Integrityالقيمة من نطاق العمودنوع البيانات، CHECK، DEFAULT، NOT NULLسعر سالب، تاريخ مستحيل
CREATE TABLE Courses (
    CourseID INT PRIMARY KEY,
    Credits  TINYINT NOT NULL CHECK (Credits BETWEEN 1 AND 6),     -- domain
    Level    NVARCHAR(10) NOT NULL DEFAULT 'Undergrad');
-- INSERT Credits = 9  → فشل: CHECK constraint
-- INSERT Students.DepartmentID = 999 (مش موجود) → فشل: FOREIGN KEY

قاعدة ذهبية: حط القيود في قاعدة البيانات مش في التطبيق فقط. التطبيق ممكن يتغير أو يتعدد (API وجوبّ وscripts)، وقاعدة البيانات هي الحارس الأخير. EF Core HasCheckConstraint وIsRequired بتولّدهم.

4) الـ NULL: أخطر قيمة في الموديل

الـ NULL معناها "غير معروف أو غير موجود"، مش صفر ولا نص فاضي. وأي مقارنة معاها نتيجتها UNKNOWN (منطق ثلاثي القيم)، مش TRUE ولا FALSE.

SELECT * FROM Employees WHERE ManagerID = NULL;     -- ما بترجعش أي صف أبداً
SELECT * FROM Employees WHERE ManagerID IS NULL;    -- الصح

-- أخطر باگ: NOT IN مع NULL
SELECT * FROM Departments WHERE DepartmentID NOT IN (SELECT DepartmentID FROM Employees);
-- لو عمود Employees.DepartmentID فيه NULL واحد → النتيجة فاضية! (لأن x NOT IN (..., NULL) = UNKNOWN)
SELECT * FROM Departments d WHERE NOT EXISTS (SELECT 1 FROM Employees e WHERE e.DepartmentID = d.DepartmentID);   -- الحل

علاقتها بالـ mapping: كل قرار "FK يقبل NULL ولا لأ" هو قرار Participation (الجزء 4 من ERD). وUNIQUE على عمود nullable بيتصرف مختلف من DBMS لـ DBMS (هنشرحه في الـ 1:1).

7) أسئلة (اضغط لكشف الإجابة)

  1. جدول فيه 5 أعمدة و 200 صف. إيه الـ degree والـ cardinality (علائقي)؟
  2. ليه ما ينفعش WHERE Phone = NULL؟
  3. إيه الفرق بين Entity Integrity و Referential Integrity؟
  4. جدول بلا PK، هل هو relation بالمعنى النظري؟
  5. مبرمج حذف صف في Departments وفيه موظفين بيشاوروا عليه، من غير FK. إيه اللي يحصل؟
  6. ليه "الربط بالقيمة" ميزة؟
  7. استعلام NOT IN رجع فاضي رغم إن فيه بيانات. أول حاجة تتأكد منها؟
الإجابات

(1) degree = 5، cardinality = 200. (2) أي مقارنة مع NULL نتيجتها UNKNOWN فبتتعامل كـ FALSE، استخدم IS NULL. (3) الأول عن PK (مش NULL ومش مكرر)، والتاني عن FK (لازم يشاور على موجود). (4) لأ، لأن relation مجموعة بلا تكرار، والـ PK هو اللي يضمن ده. (5) الموظفين يفضلوا بـ DepartmentID لقسم مش موجود (orphans)، وأي join بيخسرهم والتقارير غلط. (6) لأنه بيفصل المنطق عن التخزين، فتقدر تغيّر الـ indexes والفيزيائي من غير ما تكسر الاستعلامات. (7) هل subquery فيها NULL؟ لو آه استخدم NOT EXISTS أو IS NOT NULL جوه الـ subquery.
